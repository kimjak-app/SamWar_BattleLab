# T08 Battle UI Implementation Master Plan

## 1. 문서 목적

이 문서는 삼국WAR 전투 UI/UX의 제작 원칙, 역할 분담, 구현 순서, 승인 기준을 고정하는 마스터 기준 문서다.

향후 새 채팅, 새 세션, Codex 작업, Godot 구현에서도 이 문서를 먼저 읽고 동일한 방향을 유지한다.

## 2. 최종 목표

- 승인된 전투화면 초안을 실제 Godot 전투 UI로 구현한다.
- 새로운 UI를 다시 창작하지 않는다.
- 초안의 구조·비율·배치·화면 점유율·색상 구분을 유지한다.
- 랑그릿사급 상용 전략 RPG UI 퀄리티를 목표로 한다.
- 삼국WAR 고유의 동양 전쟁·전략 감성을 유지한다.

## 3. 공식 마스터 디자인

현재 승인된 전체 전투화면 초안을 공식 마스터 디자인으로 취급한다.

다음 요소는 임의 변경 금지다.

- 상단 중앙 HUD의 전체 실루엣과 화면 점유율
- 좌측 아군 청색 / 우측 적군 적색 구분
- 중앙 턴 프레임의 형태와 위치
- 좌측·우측 세로 장수 로스터
- 하단 행동 주체·대상 비교 정보창
- 우하단 전역 명령 3개
- 전체 UI의 상대적 위치와 전장 가시성

새로운 스타일을 제안하거나 임의로 재해석하지 않는다.

## 4. 핵심 제작 원칙

### 4.1 초안 재현 우선

승인 기준은 새로운 디자인의 화려함이 아니라 초안 재현율이다.

비교 항목:

- 구조
- 위치
- 비율
- 크기
- 실루엣
- 색상 역할
- 화면 점유율
- 전장 가시성

### 4.2 전체 화면 승인 → 부품 분리 → Godot 적용

항상 다음 순서를 지킨다.

1. 전체 전투화면 맥락에서 디자인을 확인한다.
2. 김작이 전체 화면 기준으로 승인한다.
3. 승인된 디자인에서 실제 자산을 분리한다.
4. PNG/SVG/NinePatch 등 생산용 자산으로 정리한다.
5. Godot 기존 기능 노드에 바인딩한다.
6. F5/F6 QA를 통과한 뒤 다음 부품으로 이동한다.

고립된 부품 이미지를 먼저 만들어 전체 스타일을 흔드는 방식은 금지한다.

### 4.3 구조와 재질 분리

정확한 형태와 치수는 생성형 이미지에 맡기지 않는다.

구조 담당:

- SVG
- 벡터 도형
- Photoshop/Figma 도형 레이어
- Godot Control / Panel / TextureRect
- 수치화된 좌표와 크기

재질 담당:

- 금속 질감
- 청색·적색 칠기 질감
- 절제된 금장 문양
- 하이라이트
- 그림자
- 표면 마모와 깊이감

형태는 먼저 잠그고 재질은 그 위에 입힌다.

### 4.4 기능과 이미지 분리

이미지에 다음 정보를 굽지 않는다.

- 턴 숫자
- 기세 숫자
- 장수명
- 병력 수치
- 상태 문구
- 버튼 상태 텍스트

동적 정보는 Godot Label/Control/TextureRect 등으로 표시한다.

## 5. 역할 분담

### 김작

- 총괄 PM 및 아트 디렉터
- 디자인 방향 결정
- 전체 화면 기준 승인/수정 판단
- 실제 Godot 화면 최종 QA

### 채코치

- UI 구조 분석
- 제작 규격 수치화
- SVG/PNG/NinePatch 등 UI 자산 설계 및 제작
- 전체 화면 합성 시안 제작
- Godot 적용 구조 설계
- Codex 작업 지시문 작성
- 구현 결과 감사 및 QA 기준 관리

### Codex

- 승인된 자산과 규격을 Godot에 바인딩
- 기존 기능 보존
- 스크립트 연결
- 테스트 및 문서 갱신

Codex가 새로운 디자인을 임의로 결정하지 않는다.

## 6. Godot 적용 원칙

- 기존 기능형 HUD 노드는 최대한 유지한다.
- 교체 대상은 주로 프레임·배경·아이콘·표면 스타일이다.
- Label, Control, 슬롯, 턴/기세 갱신 로직은 재사용한다.
- 디자인 변경 때문에 전투 로직을 다시 작성하지 않는다.
- 기존 전투 기능을 깨뜨리는 UI 교체는 허용하지 않는다.

## 7. 상단 HUD 기준

현재 Godot에는 이미 다음 기능 구조가 존재한다.

- 아군 기세 슬롯 10개
- 적군 기세 슬롯 10개
- 아군/적군 기세 숫자
- 전체 턴 숫자
- 턴 주체 문구
- 전투 상태 문구

따라서 상단 HUD는 새 기능을 만드는 작업이 아니라 기존 기능형 HUD에 승인된 외형을 입히는 작업이다.

### 상단 HUD 구현 원칙

- 기존 10칸 슬롯을 유지한다.
- 슬롯 개수와 간격은 Godot에서 정확히 관리한다.
- 프레임 이미지에는 슬롯 수를 굽지 않아도 된다.
- 기세 증가 시 앞쪽 슬롯부터 점등한다.
- 기세 감소/소비 시 해당 슬롯을 소등한다.
- 아군 ON은 청색, 적군 ON은 적색, OFF는 어두운 중립색으로 표시한다.
- 중앙 턴 값은 동적으로 갱신한다.
- 초안의 얇고 긴 화면 점유율을 유지한다.

각 단계는 `제작 → 전체 화면 승인 → 자산 분리 → Godot 적용 → QA PASS` 후 다음 단계로 진행한다.

## 9. QA 기준

### 시각 QA

- 초안 구조와 일치하는가
- 전장을 과도하게 가리지 않는가
- 좌우 대칭과 정렬이 정확한가
- 1920×1080 기준 위치가 안정적인가
- 텍스트가 장식과 충돌하지 않는가

### 기능 QA

- 기세 값과 슬롯 점등 수가 일치하는가
- 턴 숫자가 실제 전투 진행에 맞게 갱신되는가
- 기세 획득/소비 직후 즉시 갱신되는가
- 컷인 후 UI 상태가 정상 복귀하는가
- 저장/불러오기 후 값이 정상 복원되는가
- F5/F6에 오류·경고·깨진 노드가 없는가

## 10. 금지 사항

- 초안과 무관한 새 UI 스타일 생성
- 전체 화면 승인 전 독립 부품 확정
- 이미지에 동적 숫자/문구 굽기
- 슬롯 개수 같은 정확한 구조를 생성형 이미지에 의존
- 기능 노드 삭제 후 디자인부터 다시 만드는 작업
- 사용자 승인 없이 생산 자산 확정
- 실제 투명도를 확인하지 않고 투명 PNG라고 선언

## 11. 세션 시작 규칙

새 채팅 또는 새 작업 세션에서는 다음 순서로 시작한다.

1. 이 문서를 읽는다.
2. 승인된 전체 전투화면 초안을 확인한다.
3. 현재 Godot 구현 상태와 GitHub 기준선을 확인한다.
4. 직전 승인 부품과 다음 미완료 부품을 구분한다.
5. 한 번에 한 부품만 완료한다.

## 12. 현재 다음 작업

현재 다음 작업은 `T08-3 상단 HUD 실전 구현`이다.

먼저 현재 `Battle_Land.tscn`의 상단 HUD 노드 좌표·크기·슬롯 구조를 감사하고, 승인된 전체 전투화면 초안과 대응되는 정확한 제작 규격을 작성한다. 그 후 전체 화면 안에서 상단 HUD 적용 시안을 승인받고 생산 자산으로 분리한다.
