- **깨진 문맥 판정**: 지시서는 "엔진의 `worldmap_battle_context`가 비어 있으면"이라고 했다. [사실] 장수 키가 빠진 문맥은 엔진이 `worldmap_battle_context`를 비우지 않고, 장수 요청이 없으니 표본 장수로 채운다(`_apply_worldmap_context_side_roster`의 `allow_sample_fallback`). 그래서 더 엄격하게 판정했다: 엔진 값 읽기만으로 ① `worldmap_battle_context`가 비었거나 ② `worldmap_context_roster_summary`의 아군·적군 어느 쪽이든 `requested_hero_ids`가 비었거나 `resolved_count`가 0이면 "적용 실패" → 랩을 닫고 시작 패널, 경고 줄 1개. 엔진 쓰기 0(`engine.get`만, 새 `engine.call` 0개).
- **setup 메타**: 문맥 모드는 `samwar_battle_setup`을 세우지 않는다. 남아 있던 setup 메타도 랩을 만들기 전에 기존 `_close_lab()`이 지운다(테스트가 일부러 남겨 두고 확인: 아군 병력이 1/4로 줄지 않고 문맥 값 그대로).
- **"다시 시작/시나리오 선택" 버튼**: 문맥 모드에서 숨기고, `restart()`는 아무것도 하지 않는다(메타가 이미 소비되어 같은 문맥을 다시 시작할 수 없음). 결과창 자체(`_show_result`)는 그대로.
- **문맥 만들기(답신 1 이후)**: 테스트는 `WorldMap.tscn`을 루트 자식으로 인스턴스하고 `_build_player_attack_battle_context(…, "manual", [hero_id], {hero_id: 1}, supply_cost)`(인자 `Array[String]`)로 문맥을 만든 뒤 출정 확인이 더하는 6개 필드를 같은 이름으로 더한다. 출정 확인 전체 흐름은 roundtrip 테스트가 다룬다.
- **병력 비교**: [사실] 엔진은 문맥의 4번째 이후 장수를 지원 슬롯(`*_reinforce_*`)에 넣고 시작 때 배치하지 않는다(`is_deployed = not slot_id.contains("_reinforce_")`). 그래서 테스트는 "문맥의 모든 장수가 엔진에 그 병력으로 있다 + 3D에 보이는 부대는 문맥 부대뿐 + 3D 보임 = 엔진 배치 여부"로 단언했다(계산 없이 문맥 키 값만 비교).
- **CI 등록 위치**: battle3d 테스트들은 첫 목록(C-track Godot tests)에 있고, 네 목록이 인덱스 하나를 이어 쓴다. 그 목록 안에 넣으면 뒤의 약 30개 테스트의 shard가 모두 바뀐다. 기존 항목의 shard를 바꾸지 않도록 **마지막 목록 끝**에 한 줄 넣었다 → 인덱스 198 → shard 2(추가 전 shard 2·3이 49개로 가장 가벼움). 로컬 28초로 `timeout 300s` 안. [추정] `feature/wm3d-cityhud-20261105`도 같은 자리에 두 줄을 넣었으므로, 두 가지를 합칠 때 그 자리에서 충돌이 나고 인덱스를 다시 맞춰야 한다.
- **검증기 갱신**: `validate_battle3d_contract.py`는 `test_battle3d_*.gd` 전부에서 `WorldMap.tscn` 글자를 금지한다. 지시서가 테스트 이름(`test_battle3d_…`)과 "실제 월드맵이 만든 문맥"을 둘 다 정했으므로 충돌한다. `engine_host`만 `Battle_Main.tscn`을 허용하는 기존 방식과 같게 **이 테스트 파일 하나만** "정확히 1번"으로 허용했다(3D 스크립트·다른 테스트는 그대로 금지). 변조 시험: 셸에 `WorldMap.tscn`을 넣으면 exit 1, 테스트에 한 번 더 넣으면 exit 1, 원복 뒤 exit 0.
