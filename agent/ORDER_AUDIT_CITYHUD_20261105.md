## 1. 조사 항목 (보고서 표로)
1. **성 아이콘 클릭 경로**: 3D 월드맵에서 도시 클릭이 지금 어떻게 처리되는지(어댑터·호스트·`city_selected` 신호·main의 도시 선택/도시 패널 경로). 클릭 시 열리는 현재 패널(`WorldMapCityPanel.tscn` 등)과 새 허드창이 들어갈 자리(같은 창 안/별도 창/팝업).
2. **테크 완료 데이터**: `city_domestic_tech_completed`의 저장·읽기 위치(`worldmap_main.gd` `_player_state`, 저장 직렬화), 도시별 테크 완료 조회 API가 main 밖에서 쓸 수 있는지(`domestic_tech_*` 서비스 파일), 테크 완료 이벤트/신호가 있는지(건물이 켜지는 순간 갱신 방법).
3. **건물 ↔ 테크 id 매핑표**: `ASSET_LIST_KO.md`의 건물 30종이 `domestic_tech_catalog.gd`(도시 53) 실제 id와 모두 맞는지 id 단위 대조(없는 id, 이름 다른 id, 중복 "창고"). 생활 5종처럼 id가 없는 건물의 현재 데이터상 근거. 결과를 표로(건물 / 파일명 / 테크 id / 카탈로그에 존재 / 비고).
4. **도시 데이터**: 13개 도시의 지역(한·중·일·몽골) 판정 방법(스타일 kr/cn/jp 선택 근거, 카라코룸·몽골은 그림 3지역 중 어디에 매핑되는지 [미확인]이면 질문으로), 도시 타입(`coastal_trade_city` 등)과 해안 건물 조건(`worldmap_main.gd:597-610`), 해안 도시가 지금 교토·큐슈 2곳뿐인지.
5. **에셋 반입 형태**: 90장을 레포 어디에 두는 것이 기존 규칙에 맞는지(`assets/worldmap/city_icons/`, `assets/ui/` 구조와 `agent/WORLDMAP_RULES.md`의 `.import` 규칙, `.gdignore`, 모바일 제외 여부, 용량). 이름 규칙 `bld_<테크id>_<kr|cn|jp>.png`와 코드에서 로드하는 방법(경로 조합, `ResourceLoader.exists` 폴백). `.import` 파일이 몇 개 생길지.
6. **허드창 구현 위치 판단**: 새 씬·스크립트를 둘 폴더(기존 폴더 중 규칙에 맞는 곳, 새 폴더 금지 원칙과의 충돌 여부), 월드맵 HUD(2D `CanvasLayer`)와의 입력·z-순서 충돌 여부, 3D 레이어(`CanvasLayer -10`)와 `SubViewportContainer`와의 상호작용, 창이 열린 동안 3D 카메라 입력 차단 방법(`external_input_block` 등 기존 수단).
7. **`worldmap_main.gd` 수정 필요 여부**: 허드창을 열려면 main에서 고쳐야 하는 줄이 있는지(도시 클릭 분기, 신호 연결). 없이 호스트·새 스크립트만으로 가능한지 판단하고, 필요하면 줄 수와 핀 재고정 영향, 2-E·M7과 한 번에 묶을 수 있는지.
8. **성 안 배치 데이터**: 계획서 §3(배치 원칙)·§6(샘플 성 4개 레이아웃)이 코드로 만들어야 하는 "슬롯 좌표 데이터"가 무엇인지(도시별 슬롯 JSON/Dictionary 필요 항목), 샘플 4성(한성·평양·건업·에도)+교토 시연의 슬롯 수 추정, 그림의 앵커(하단 중앙)와 슬롯의 관계.
9. **성능·메모리**: 90장 합계 2.6 MB(압축 전 파일 기준), 텍스처 임포트 후 VRAM 대략(장수·해상도 합 계산은 PNG 크기에서 산출), 허드창이 열릴 때만 로드할지 여부, 07의 메모리 프로브(`wm3d_mem_log.csv`)로 측정 가능한지.
10. **약한 에셋 8개**(README_KO "약한 항목")는 반입을 막는 항목인지 후속 교체 후보인지, 교체 시 파일명 유지로 코드 변경 0이 되는지.
