## 4. 새 시험 `tests/scripts/test_battle3d_command_panel.gd` — 62 checks, 실패 0 (Windows, 단독 3회째)

1. 랩 5버튼·방향 줄이 화면 밖이고 정보 상자가 숨음(1920×1080, 1280×800). 패널 층 7. 패널만 마우스를 받고 화살표 층은 받지 않음.
2. 시작(이순신): 패널이 열리고 글·`disabled`·툴팁이 랩 버튼과 같다. 자리는 2D 규칙으로 다시 계산한 값과 같고, 유닛 근처 후보 8곳 중 하나이며, 화면 안이다. 시작 상태: 기본공격 켜짐, "학익진 · 기세 4" 꺼짐, 책략 꺼짐, 방어 켜짐, 대기 켜짐.
3. N7 = 엔진 값이고, 엔진 지문은 그대로다.
4. 카메라 yaw 0.32/1.2/-0.9 × 줌 20/45/70(9가지): 매번 패널이 2D 규칙대로 유닛을 따라가고 화면 안이다. 줌 20으로 판 반대쪽을 비춰 유닛이 화면 밖이면 숨는다. 돌아오면 다시 열린다.
5. **실제 마우스 클릭**(이동·누름·뗌을 `Window.push_input`으로) 대 랩 버튼 `pressed.emit()`. 같은 시작에서 이순신·정도전 × 5버튼:

   | 버튼 | 이순신 | 정도전 | 첫 엔진 쓰기 → 끝 단계 |
   |---|---|---|---|
   | 기본공격 | 켜짐 | 켜짐 | `try_basic_attack` → attack_select |
   | 고유특기 | 꺼짐 | 켜짐 | `_on_unique_skill_button_pressed` → unique_skill_target_select |
   | 책략 | 꺼짐 | 꺼짐 | — |
   | 방어 | 켜짐 | 켜짐 | `_on_defend_button_pressed` → (적 턴 뒤) ally_turn |
   | 대기 | 켜짐 | 켜짐 | `_end_ally_turn_by_wait` → (적 턴 뒤) ally_turn |

   - 켜진 버튼: 패널 클릭과 랩 버튼의 **엔진 지문이 같다**. 그 명령이 첫 쓰기이고 횟수가 같다.
   - 꺼진 버튼: 실제 클릭이 아무 쓰기도 부르지 않고 엔진이 그대로다.
   - 공격 대상 고르기에서는 패널이 숨고, 취소하면 다시 규칙대로 열린다.
6. **방향 화살표 4개**: 각 방향마다 새 판에서 아군을 고르고 칸을 클릭해 이동한다. facing_select가 되면 화살표가 뜨고 패널은 숨는다.

   - 카메라 yaw를 1.4로 돌리면 화살표는 따라가고 글자는 그대로다.
   - **실제 클릭**으로 엔진 쓰기 `_select_post_move_facing` 1개, 엔진 방향 = 그 방향(up/down/left/right 4번 모두), 단계 ally_turn, 화살표 숨김.
7. 수동 구간(패널 [대기]를 실제 클릭으로 8번): 2,236프레임 매 프레임 패널 = 랩 상태. 1프레임 늦음 8, 기타 0.

## 10. 김작이 정할 것

1. [책략] 활성이 2D(사거리 무관)와 다르다(§0-2). 랩 규칙(사거리 안 적 필요)을 그대로 둘지.
2. 툴팁: 2D의 고유특기 툴팁(설명 + 기세)을 쓸지, 지금처럼 랩 사유를 쓸지.
3. 패널 기준점 높이 1.6m(§0-4)와 기본 줌에서 화살표가 칸보다 큰 것(49×50 대 칸 49×34, §0-6). 글자 크기를 줄일지.
4. 패널 자리가 소수 픽셀이라 글자가 조금 흐리다(§7). 정수 자리로 맞출지.
