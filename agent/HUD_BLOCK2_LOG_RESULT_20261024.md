## 0. 먼저 알릴 것 (시점, 사실)

1. **엔진 로그는 3D 재생보다 먼저 바뀐다(측정).**
   - 기본 배치에서 이순신 [대기]를 누른 프레임(1번째 프레임)에 엔진 로그 맨 아래 줄이 이미 "관우 접근"이다. 적 슬롯을 엔진이 그 자리에서 처리했다.
   - 3D 랩은 같은 프레임에 적 재생을 시작한다(`enemy_texts`가 1번째 프레임에 늘어남). 재생이 다 끝난 것은 64번째 프레임이다(이때 로그에 "아군 턴 복귀"가 붙는다).
   - 따라서 **화면 로그는 3D가 관우의 이동을 보여 주는 동안(약 63프레임, 60fps라면 약 1초) 이미 "관우 접근"을 보여 준다.**
   - 지시대로 늦추지 않고 즉시 표시로 두었다(정하지 않음 → 김작이 정할 것 1).
2. **화면 로그는 엔진보다 최대 1프레임 늦게 바뀔 때가 있다(측정).**
   - 엔진은 일부 로그 줄을 Tween·타이머 콜백 안에서 쓴다. Godot는 그 콜백을 노드 `_process` 뒤에 돌린다. 패널은 셸의 `_process`(랩 다음, 상단 HUD와 같은 자리)에서 채우므로, 그런 줄은 다음 프레임에 보인다.
   - 승리 연습 [자동] 한 판: 보인 1184프레임 중 **86프레임이 1프레임 늦음**, 엔진에 없던 글을 보인 프레임 **0**.
   - 2D는 `_append_battle_log` 안에서 바로 HUD를 갱신해서(C:6781-6786) 이 늦음이 없다.
3. 로그 글은 2D와 같다. 엔진 배열을 2D처럼 `"\n".join`으로 잇는다(C:15930-15931, 2D는 줄 앞에 "- "를 붙이지 않음). 시작 때 글은 "월드맵 전투 데이터 없음 · 테스트 전투"다(엔진이 테스트 전투에서 쓰는 줄).
4. 결과가 나오면 패널을 상단 HUD와 함께 숨긴다(2D가 결과 확정 때 `ProductionHudRoot`를 숨기는 것과 같다, C:15908).

## 2. 새 시험 `test_battle3d_log_hud.gd`

게임 창 1920×1080, 셸 그대로. 기대 글은 시험이 엔진 배열로 따로 만든다(`"\n".join(engine.battle_log_lines)`).

1. 시작 화면: 패널 숨김. 기본 배치 시작: 패널이 2D 자리(39..301 × 793..1055)에 있고 글 = 엔진 줄
2. 패널이 랩의 보이는 UI(정보 상자·행동 버튼·도움말 등)와 안 겹침
3. **읽기 전용**:
   - 읽기 100번 뒤 엔진 상태(부대 지문·컨트롤러 상태·로그 4종·기세·쓰기 목록·로그 배열·단계)가 그대로다.
   - 돌려받은 복사본에 줄을 넣거나 바꿔도 엔진 배열은 바뀌지 않는다.
4. **4줄 제한**:
   - 엔진 자신의 `_append_battle_log`로 줄 5개를 넣는다. 줄마다 패널 = 엔진이다.
   - 5번째 줄이 들어가면 가장 오래된 줄이 빠진다. 엔진 배열과 패널이 모두 정확히 "시험 줄 2~5"가 된다.
5. 바뀐 것이 없으면 다시 적용하지 않는다(20프레임).
6. **[대기] → 적 슬롯 → 아군 차례 복귀의 모든 프레임**: 패널 = 이번 프레임의 엔진 줄이거나, 지난 확인 뒤 엔진이 거쳐 간 상태(4줄 창)다. 엔진에 없던 글은 0이다. 재생과의 시점 차이를 프레임으로 잰다(§0-1).
7. **승리 연습 [자동] 한 판의 모든 보인 프레임**: 6과 같은 검사. 결과 뒤 패널 숨김.
