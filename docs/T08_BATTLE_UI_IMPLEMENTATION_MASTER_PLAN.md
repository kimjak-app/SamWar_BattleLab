## 0. 최우선 고정 계약

### 공용 기세 계약

- 시작 기세: **3**
- 최대 기세: **10**
- 아군·적군 각각 기세 슬롯 **10칸**
- 화면 시작 표시는 `3 / 10`
- 현재 기세만큼 슬롯이 활성화되고 나머지는 비활성화
- 기세 값과 슬롯 표시는 실제 전투 데이터에 실시간 연동
- 숫자·슬롯 상태는 이미지에 굽지 않고 Godot 노드로 처리

이 계약은 T08 전투 UI 구현 중 임의로 변경하지 않는다.

---

## 1. 목적

- 승인된 전투 UI 초안을 실제 Godot UI로 구현한다.
- 새로운 UI를 임의로 창작하지 않는다.
- 승인된 초안의 구조·비율·위치·화면 점유율을 유지한 채 게임에서 실제로 작동하게 만든다.
- 비주얼과 기능을 분리하되, 최종 QA에서는 둘을 함께 검증한다.

## 2. 핵심 원칙

### 2-1. 초안 우선

- 승인된 전투화면 초안은 공식 마스터 디자인이다.
- 구조·비율·위치·실루엣·화면 점유율은 임의로 변경하지 않는다.
- “비슷한 새 디자인”을 만들지 않는다.
- 변경이 필요할 때는 전체 화면에서 먼저 비교·승인한다.

### 2-2. 레이어 분리

전투화면을 다음 레이어로 분해한다.

| # | 레이어 | 예시 | 담당 | 산출물 |
|---|---|---|---|---|
| 1 | 배경 아트 | 지형·성곽·숲 | 채코치 | 배경 이미지 |
| 2 | 캐릭터 초상화 | 장수 얼굴·흉상 | 채코치 | 투명 PNG |
| 3 | 유닛 스프라이트 | 보병·궁병·기병 | 채코치 | 투명 PNG |
| 4 | 프레임·재질 장식 | 액자·금속·칠기·문양·광택 | 채코치 | 전용 PNG/SVG 또는 9-slice |
| 5 | 기능 오버레이 | 선택 강조·범위 표시 등 | Codex | Godot 노드·코드 |
| 6 | 정보 UI | 기세·HP·턴·스탯·로그 텍스트 | Codex | Control 노드 조합 |

### 2-3. 절대 금지

- 기세 수치, 턴 숫자, HP 수치, 로그 텍스트를 이미지에 굽지 않는다.
- 정확한 슬롯 개수나 기능형 게이지를 이미지 생성에 맡기지 않는다.
- 승인된 초안과 다른 실루엣을 “고급화”라는 이유로 새로 만들지 않는다.
- 현재 전투 시스템에 없는 기능을 UI 문서만으로 선행 구현하지 않는다.

## 3. 승인 및 제작 흐름

### 3-1. 전체 배치 구조 승인

첫 단계의 산출물은 정밀 일러스트가 아니라 **와이어프레임 또는 현재 Godot 화면 배치도**다.

확인 항목:

- 상단 HUD 위치
- 좌·우 장수 로스터 위치
- 하단 행동정보창 위치
- 명령 버튼 위치
- 로그창 위치
- 각 영역의 크기와 화면 점유율

이 단계에서는 “어디에 무엇이 있는가”만 잠근다.

### 3-2. 부품 분리

배치 승인 후 다음 단위로 나눈다.

1. 상단 HUD
2. 좌측 장수 로스터
3. 우측 장수 로스터
4. 하단 행동정보창
5. 명령 버튼
6. 로그창

각 부품은 먼저 어떤 레이어가 결합되는지 명시한다.

### 3-3. 부품별 전체화면 합성 승인

- 부품을 단독 이미지로만 승인하지 않는다.
- 실제 1920×1080 전투화면에 합성한 상태로 먼저 확인한다.
- 전체화면에서 승인된 뒤에만 투명 PNG·SVG·9-slice 등으로 추출한다.

### 3-4. Godot 적용

- 기존 기능 노드와 데이터 바인딩은 최대한 유지한다.
- 프레임·배경·아이콘만 교체하거나 아래 레이어에 추가한다.
- 기능형 요소는 기존 Control 노드 위에 배치한다.

### 3-5. QA

- 비주얼 기준과 기능 기준을 모두 통과해야 한다.
- 하나라도 실패하면 QA PASS로 인정하지 않는다.

## 4. 에셋 제작 스펙

### 4-1. 배경 아트

```text
해상도: 1920×1080
포맷: PNG 또는 프로젝트 기준 포맷
스타일: 기존 승인 배경 화풍 유지
구도: 중앙 전투 공간 확보
제외: 캐릭터, UI, 텍스트, 숫자, 게이지, 그리드선
```

### 4-2. 캐릭터 초상화

```text
기준 해상도: 512×512
포맷: 완전 투명 PNG
구도: 흉상~반신
제외: 배경, 텍스트, 프레임
파일명: authoritative general_id 기준
저장 경로: 실제 런타임 자산 디렉터리 감사 후 확정
```

#### 39명 초상화 운용 원칙

39명 전체를 즉시 신규 제작하지 않는다.

1. 기존 장수 초상화 전수 감사
2. 재사용 가능 / 보정 필요 / 신규 필요로 분류
3. 교체 대상만 확정
4. 기준 장수 1명의 최종 스타일 승인
5. 이후 5명 단위 배치로 진행
6. 직전 승인본을 다음 배치의 스타일 레퍼런스로 사용
7. 스타일 드리프트 발생 시 해당 배치를 승인하지 않는다

### 4-3. 유닛 스프라이트

```text
기준 해상도: 128×128
포맷: 투명 PNG
대상: 실제 MVP 병종 범위에 맞춰 감사 후 확정
원칙: 장수별 신규 제작이 아니라 병종별 재사용
```

### 4-4. 프레임·재질

프레임은 모두 동일한 9-slice로 처리하지 않는다.

#### 9-slice 적용 대상

- 일반 정보패널
- 로그창
- 공통 버튼
- 반복 사용되는 단순 액자

#### 전용 자산 적용 대상

- 상단 HUD 전체 실루엣
- 중앙 턴 프레임
- 장수 카드 고유 외곽
- 초안의 상징적인 비정형 장식

#### 공통 기준

```text
포맷: 투명 PNG 또는 SVG
텍스트·숫자·기능형 슬롯 제외
좌우 대칭과 기준 치수 보장
Godot 적용 전 실제 화면 합성 승인 필수
```

## 6. Godot 구현 스펙

### 6-1. 기존 노드 유지

- 현재 `Battle_Land.tscn`의 기능형 HUD 구조를 우선 재사용한다.
- 기존 Label, ProgressBar, Control, Container, Signal 연결을 불필요하게 재작성하지 않는다.
- 새 그래픽은 기존 기능 노드 아래 또는 배경 레이어에 배치한다.

### 6-2. 기세 게이지

```text
구현: HBoxContainer + 슬롯 Control 또는 TextureRect 10개
시작값: 3
최대값: 10
아군 슬롯: 10개
적군 슬롯: 10개
표시: 시작 시 양쪽 3칸 활성
갱신: 실제 기세 데이터 변경 시 즉시 반영
숫자: Label로 "현재 / 10" 표시
활성 상태: 아군 청색 계열 / 적군 적색 계열
비활성 상태: 어두운 중립색
```

테스트 단계에서는 정사각형 슬롯을 허용한다. 최종 아트 승인 후 다이아몬드 또는 승인된 슬롯 텍스처로 교체할 수 있다.

### 6-3. 전체 턴 표시

```text
구현: Label
표시 예: 1 / 30
갱신: 실제 전투 턴 데이터와 연동
중앙 턴 프레임 이미지는 배경 장식만 담당
숫자·진영 턴 문구는 Godot 노드로 표시
```

### 6-4. 병력 HP바

```text
구현: ProgressBar + 커스텀 StyleBox
아군: 청색 계열
적군: 적색 계열
현재/최대 병력: Label 오버레이
실제 병력 데이터와 연동
```

### 6-5. 하단 스탯 패널

```text
구현: GridContainer 또는 HBoxContainer
아이콘: 소형 투명 에셋
숫자·설명: Label
프레임: 승인된 공용 또는 전용 프레임
```

### 6-6. 로그창

```text
구현: RichTextLabel 또는 VBoxContainer
스크롤 지원
실제 전투 로그 데이터 표시
프레임은 별도 장식 레이어
```

### 6-7. 그리드·이동 범위

현재 T08 MVP 필수 범위에 포함하지 않는다.

- 현재 전투 시스템에 실제 타일 이동·이동력·사거리 계약이 존재하는지 먼저 감사한다.
- 존재하지 않으면 구현하지 않는다.
- 필요 시 미래 확장 문서에서 별도 설계한다.
- UI 개선을 이유로 새로운 전투 규칙을 임의로 추가하지 않는다.

## 8. 승인 기준

### 8-1. 비주얼 기준

- 초안 구조 재현
- 위치
- 비율
- 크기
- 실루엣
- 화면 점유율
- 좌우 균형
- 배경과의 가독성
- 전체 디자인 언어의 일관성

### 8-2. 기능 기준

- 시작 기세가 정확히 `3 / 10`으로 표시되는가
- 아군·적군 슬롯이 각각 정확히 10개인가
- 기세 증가·소비 시 활성 슬롯과 숫자가 함께 갱신되는가
- 전체 턴 값이 실제 전투 턴과 일치하는가
- 병력 HP바가 실제 병력 수치와 일치하는가
- 로그창이 실제 전투 로그를 표시하는가
- 컷인 재생 후 HUD 상태가 정상 복원되는가
- 저장·불러오기 후 HUD 값이 실제 데이터와 일치하는가
- 화면 전환과 데이터 갱신이 기존 Signal·refresh 흐름을 깨지 않는가

### 8-3. PASS 원칙

- 비주얼만 통과하고 기능이 실패하면 PASS가 아니다.
- 기능만 작동하고 초안 재현도가 부족해도 최종 PASS가 아니다.
- 두 기준을 모두 통과해야 다음 부품으로 진행한다.

## 9. T08-3 첫 수직 슬라이스

첫 검증 대상은 상단 HUD다.

### 작업 범위

- 현재 Godot 상단 HUD 배치와 기능 노드 감사
- 승인 초안의 상단 HUD 실루엣 수치화
- 슬롯·텍스트 없는 전용 프레임 제작
- 실제 전투화면 합성 시안 승인
- 기존 아군·적군 10칸 유지
- 시작값 `3 / 10`
- 중앙 전체 턴 `1 / 30`
- 실제 기세와 턴 데이터 연동
- F6 기능·비주얼 QA

### 성공 기준

1. 승인 초안의 상단 HUD가 실제 전투화면에 자연스럽게 적용된다.
2. 아군·적군 각각 10칸이며 시작 시 3칸이 활성화된다.
3. 기세 변화가 슬롯과 숫자에 즉시 반영된다.
4. 전체 턴이 실제 전투 진행에 따라 갱신된다.
5. 기존 전투·고유기·컷인·저장 흐름이 깨지지 않는다.
6. 김작이 “초안의 상품성이 실제 게임에 살아 있다”고 승인한다.

T08-3이 PASS되면 동일한 공정을 나머지 전투 UI 부품에 반복한다.
