## 1) 커밋 A — 명령 패널이 HUD도 피함

- 셸 `hud_rects()`(`battle3d_scenario_shell.gd:471`)가 HUD 사각형 목록을 낸다. 카메라 가운데 맞춤(`:479`)과 패널 상태(`:376` `"hud_rects"`)가 같이 쓴다.
- 패널 `choose_position()`(`battle3d_command_panel.gd:130-171`): 2D 점수는 그대로 두고, 그 위에서 아래 순서로 거른다.
  1. 2D 규칙이 고른 자리가 표식과 HUD 둘 다 안 겹치면 그대로.
  2. 아니면 가까운 후보 중 둘 다 안 겹치는 곳 가운데 2D 점수가 가장 좋은 곳.
  3. 없으면 모서리 후보 중 둘 다 안 겹치는 곳. **부대에서 멀어진다.**
  4. 그래도 없으면 4-6b 방식(표식만 피함). 그것도 없으면 2D 자리.
- **모서리로 간 실제 예** [사실: 캡처 `_04`]: 줌 30에서 부대를 화면 왼쪽 끝(앵커 x 420)으로 밀었다. 가까운 후보 중 HUD와 표식을 둘 다 피하는 곳이 없어서 패널이 **오른쪽 아래 모서리**로 갔다. 로스터·표식과는 안 겹치지만 부대와 멀다.
- **결과** [사실, 고친 뒤 probe와 시험]: 위 표 15개 경우 모두 실제 패널이 HUD와 겹치지 않는다(`probe_after_A.log`).
- **오른쪽 가장자리** [사실]:
  - 4-6 때 적군 로스터를 덮던 것은 **4-6b의 표식 피하기만으로 이미 사라져 있었다.** 클코치 표의 "4-6b 오른쪽: 안 겹침"과 같다.
  - 시험의 대조에서는 HUD 피하기와 표식 피하기를 둘 다 끈 4-6 규칙으로 돌렸다. 그러면 줌 20, 부대를 x 1580까지 민 경우에 적군 로스터를 덮는다.
- 드래그, 패널 크기, 화면 안 가두기는 그대로다. 아래 기존 시험 5개는 **바꾸지 않고** 통과했다: `test_battle3d_command_panel.gd`, `…_checks.gd`, `test_battle3d_panel_drag.gd`, 4-6b `panel_avoid`, `camera_center`.
